# Расширение Chrome (MV3)

Зачем: агент (P4) вставляет текст через `SendInput` — это работает в активном
окне Windows, но не работает, если целевое поле находится во **фоновой вкладке**,
или если приложение блокирует автовставку (`Ctrl+V` в поля паролей, некоторые
банковские формы). Расширение вставляет текст прямо в DOM целевого поля.

## Установка

```bash
npm run build -w @speechpad/extension
```

1. `chrome://extensions` → включить «Режим разработчика».
2. «Загрузить распакованное расширение» → папка `apps/extension/dist`.
3. Значок расширения должен показать бейдж `ok` (значит, локальная страница
   Speechpad зарегистрирована как источник). Бейдж `off` — вкладка
   `http://127.0.0.1:8787/` не открыта.

Перезагрузить расширение после `npm run build` — не требуется, страницу
`127.0.0.1:8787` нужно перезагрузить.

## Использование

В главном окне появляется список «Куда вставлять»:

| Маршрут | Куда уходит финальная фраза | Когда нужен |
| --- | --- | --- |
| В активное окно Windows | сфокусированное поле любой программы | Word, Блокнот, Telegram, обычные веб-формы |
| В поле вкладки браузера | поле в **активной вкладке** Chrome, даже если она фоновая | пароли, iframe, редакторы, вкладки, которые нельзя типировать SendInput'ом |

Порядок работы: щёлкнуть один раз по целевому полю (расширение запоминает
последнее сфокусированное поле), вернуться в окно Speechpad, говорить.

## Архитектура

```
apps/web (127.0.0.1:8787)
   │  window.postMessage {source:'speechpad-web'}
   ▼
bridge.js  — только на 127.0.0.1/localhost, проверяет origin и source
   │  chrome.runtime.sendMessage
   ▼
background.js (service worker) — хранит авторизованные origin'ы, бейдж
   │  chrome.tabs.sendMessage в активную вкладку
   ▼
inserter.js — запоминает последнее редактируемое поле, вставляет текст
```

Агент в этой схеме не участвует: расширение не держит WebSocket и не знает
токен агента. Авторизация строится на факте, что скрипт `bridge.js` грузится
только на loopback-страницу, которую отдаёт локальный агент; удалённый сайт
не может выполнить код в этом origin (SOP) и не получает доступ к
`chrome.runtime`.

## Безопасность

- `bridge.js` подключён только к `http://127.0.0.1/*` и `http://localhost/*`,
  слушает только `event.source === window` и `isLocalOrigin(event.origin)`.
- Фоновый скрипт принимает `insert` только от origin'а, который сам
  зарегистрировался через `bridge-ready` (127.0.0.1 или localhost), и
  сверяет origin отправителя с этим списком.
- Вставка в саму вкладку Speechpad запрещена: цель выбирается как активная
  вкладка, исключая вкладку-отправителя.
- `inserter.js` не читает и не передаёт содержимое полей: он помнит только
  ссылку на элемент и вставляет присланный текст.
- Ограничение: расширение загружается на `<all_urls>` ради отслеживания
  фокуса — это требование Chrome, а не чтение данных.

## Протокол

Запрос страницы → `window.postMessage`:

```ts
{ source: 'speechpad-web', kind: 'ping' }
{ source: 'speechpad-web', kind: 'insert', text: string, seq: number }
```

Ответ расширения:

```ts
{ source: 'speechpad-extension', kind: 'ready', authorized: boolean, origins: string[] }
{ source: 'speechpad-extension', kind: 'inserted', ok: boolean, seq: number, target: string | null, message: string | null }
```

Определения и валидаторы живут в `apps/extension/src/protocol.ts` и
импортируются веб-приложением через алиас `@speechpad/extension-protocol` —
одна версия протокола на обоих концах.

## Стратегии вставки

1. `document.execCommand('insertText')` — срабатывает в `input`, `textarea`,
   `contenteditable`, работает с React/Vue/Svelte (нативная вставка).
2. `setRangeText` + событие `input` (`inputType: 'insertText'`) — запасной путь
   для полей формы.
3. Нативный сеттер `value` из прототипа + `input` — для React, который
   перехватывает `value`.
4. Для `contenteditable` — правка `Range` в каретке, иначе `appendChild`.

Текст нормализуется: хвостовые пробелы и переводы строк убираются, максимум
4000 символов на фразу.

## Ограничения

- Вставка идёт в **активную вкладку** последнего сфокусированного окна, а не в
  произвольную вкладку: Chrome не даёт расширению писать в неактивные вкладки
  без `activeTab` на конкретный таб. Для фоновой вкладки нужно, чтобы она сама
  была активна в момент вставки (то есть её можно свернуть, но не переключать).
- `chrome://`, веб-маркет и PDFViewer не принимают сообщения — это ограничение
  браузера, там работает агент.
- Расширение не распознаёт речь: микрофон остаётся в веб-приложении.
